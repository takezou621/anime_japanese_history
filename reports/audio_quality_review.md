## 1. BGM 選曲の現状

### 設計 (tools/audio/make_bgm.py `MOODS` — numpy 合成, 著作権完全クリア)

| セクション | ムード | BPM | コード進行 (root MIDI / Quality) | テクスチャ | ドラム |
|---|---|---|---|---|---|
| opening | 明るい | **120** | C→G→Am→F (48C/43G/45A/41F) | パッド0.30 + アルペジオ0.20 (8分) | kick×2/bar, hat×4 |
| story | 落ち着き | **90** | Am→F→C→G | パッド0.34 中心, アルペジオ弱め | なし |
| points | 軽快 | **110** | F→C→Dm→B♭ | スタッカート16分アルペジオ | kick×2/bar, hat×4 |
| quiz | タメ | **100** | Dm→B♭→Gm→A | パッド0.30 + 8分アルペジオ | kick×3, **snare×2**, hat×8 (全セクション最強) |
| ending | 温かい | **85** | G→D→Em→C | ソフトパッド0.34 | なし |

- 全話共通で 5 セクション構成 (opening/story/points/quiz/ending) → 全て定義済みムード (unknown 代用なし)
- 合成は bar グリッド (bar = 4×60/bpm 秒) を絶対時刻で刻むため、**BPM/コード進行は確定的にレンダされる設計パラメータ**
- 冒頭 0.6s フェードイン / 末尾 2.2s フェードアウト / セクション継ぎ目 0.25s フェード

| 項目 | 設計 | 実測 (10 話) | 判定 |
|---|---|---|---|
| ピーク正規化 | -12 dBFS | **-12.00 dBFS** (10/10 話一致) | ✓ 設計通り |
| BGM 長 = timing.total | 一致 | 全話一致 (例: ep01 571.098s / ep10 542.415s。**ep10 はテール不足 (538.6s) を確認後に BGM/mix/mp4 再生成で解消済み**) | ✓ |
| セクション別 RMS | quiz 最強 (ドラム増量) / ending 最弱 (ソフトパッド) | opening -27.5〜-28.0 / story -28.4〜-28.9 / points -27.7〜-28.2 / **quiz -26.2〜-26.7 (最強)** / **ending -29.1〜-29.6 (最弱)** dBFS — 全話で同一パターン | ✓ 設計意図どおり |
| テンポ (quiz セクション kick オンセット間隔) | 100bpm → 16分グリッド 150ms | **IOI 中央値 153ms** (ep01 quiz, 315 オンセット) | ✓ 設計通り |
| テンポ (エンベロープ FFT 逆推定) | - | 不調 (パッド主体の音圧変動が支配) — 上記 kick グリッド実測で代替 | (参考) |

## 2. ダッキング実測

### 設計 (tools/audio/make_mix.py)
- 台詞区間 BGM ゲイン **-18 dB** / 無音区間 **-8 dB** / ランプ 0.35s / ガード 0.18s / 近接区間マージン 0.88s

### 実測 (エンベロープを timing.json + bgm.wav から numpy で再現して全 10 話測定)

| 項目 | 設計 | 実測 (10 話) | 判定 |
|---|---|---|---|
| 台詞区間 BGM ゲイン | -18 dB | **-18.00 dB** (10 話全て, mean)。最小値も -18.00 (active=1 の区間) | ✓ 基準 (-18dB以下) 達成 |
| 無音区間 BGM ゲイン | -8 dB | **-8.04 dB** (ランプ中間サンプルを含む平均) | ✓ |
| ダック後 BGM RMS (台詞区間) | - | **-46.0〜-46.5 dBFS** | 台詞レベル (総合 -14.4LUFS 相当) の約 30dB 下 |
| ダック後 BGM RMS (無音区間) | - | -36.5〜-37.6 dBFS | 実効ダック深度 ≈ **9.4〜10.0 dB** (= 設計 -8→-18dB) |
| ミックス実物のギャップ区間 RMS (ep01/ep05/ep10 の ≥0.9s ギャップで実測) | - | -27.3〜-32.1 dBFS (楽曲内容による局所変動を含む) | ギャップは無音ではなく BGM (-8dB) が常時存在 |

結論: **台詞区間の BGM は設計通り -18dB に減圧され (相対ゲイン実測 -18.00dB)、BGM 単体 RMS でも -46dBFS 級で基準 (-18dB 以下) を大きく下回る。** ナレーション可聴性の阻害はない。

## 4. 無音区間の自然さ (ギャップ契約 0.45/0.7/0.9/0.7s)

### 設計・検証済み
- ギャップ契約: ビート間 0.45s / シーン間 0.7s / セクション間 0.9s / テール 0.7s — **timing.json との突合で全話全遷移が契約通り** (qa_audio_epNN.md / 最終回帰確認)
- 加重実効ギャップ: VOICEVOX の前後フェノーム無音 (~0.1-0.3s/側) が加わるため実効的な発話間隔は契約 + ~0.2-0.5s

### 実測 (ミックス実物, -38dB 閾値の実無音検出)
| 項目 | 実測 (10 話) | 評価 |
|---|---|---|
| 真の無音ラン (≥0.25s) | **1〜2 件/話のみ**, 最大 0.36〜0.72s | 冒頭フェードイン等の端部のみ。**会話中のデッドエアなし** |
| ギャップ区間の音圧 | -27〜-32 dBFS | 全ギャップで BGM (-8dB) が鳴っている → 「無音」ではなく「静かな BGM」= 不自然さなし |
| テール | BGM 2.2s フェードアウト | ep10 テール不足を確認→ BGM/mix/mp4 再生成で解消済み (542.415s, QC pass) |

評価: **ギャップ契約の妥当性は実測でも裏付けられた**。0.45s のビート間は対話テンポとして速すぎず (実効 ~0.6-0.9s)、セクション間 0.9s + BGM により区切り感が確保される。ep09 のみ総尺 598.0s で上限まで 2s (s12 短縮の備え案は audio で共有済み)。

## 5. 抑揚の効果確認 (intonationScale)

### 設定 (script.json characters — 全 10 話で一致を確認)
- ヒスト先生 (四国めたん): speed 1.18〜1.22 / pitch 0.0 / **intonation_scale = 1.05**
- マナブ (ずんだもん): speed 1.22 / pitch 0.0 / **intonation_scale = 1.35**
- 配線確認: make_narration.py が `query["intonationScale"]` に実設定を渡す (voice 質設定ハッシュで再生成管理済み)

### 実測 A: 最終レンダのナレーション WAV の F0 統計 (36 ビート: ep01/ep05/ep10 × 両スピーカ)

| スピーカ | intonation | F0 中央値 | 相対変動 (σ/median) 中央値 | p5-p95 レンジ中央値 |
|---|---|---|---|---|
| ヒスト先生 | 1.05 | 318 Hz | **0.18** | 183 Hz |
| マナブ | 1.35 | 330 Hz | **0.24** | 220 Hz |

### 実測 B: 同一話者・同一テキストでの A/B 合成 (intonationScale の純効果分離)

| 話者 | 1.0 | 1.05 | 1.35 |
|---|---|---|---|
| ずんだもん (相対変動) | 0.220 | 0.223 (+1%) | **0.241 (+10%)** |
| 四国めたん (相対変動) | 0.197 | 0.203 (+3%) | **0.246 (+25%)** |

### 評価
- **単調さは解消されている**: (a) 2 者対話による交互発話 (声質・F0 ベースが異なる), (b) BGM のセクション別ムード, (c) intonationScale 1.35 の抑揚増の 3 層で構成されている。F0 実測でもマナブのピッチ変動は先生の 1.3 倍 (相対変動 0.24 vs 0.18, レンジ 220 vs 183Hz) で、聴感上の単調さは確認されない
- ただし A/B 分離測定では **1.05 の効果は +1〜3% とほぼ無効** (1.35 は +10〜25% と有効)。先生側の単調さが気になる場合は intonationScale 1.15〜1.20 への引き上げを検討する価値あり (P3 提案)
- 補足: audio_query の kana はアクセント句の位置情報のみで抑揚パラメータの効果は転写に現れないため、本検証は合成 WAV の F0 実測で実施
